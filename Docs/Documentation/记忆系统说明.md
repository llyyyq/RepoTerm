# RepoTerm 新记忆系统说明

本文说明 RepoTerm 重构后的持久化记忆系统。系统以 `repoterm/memory/` 为唯一业务入口，使用 SQLite 保存 durable memory；旧 JSON/Markdown 文件只作为迁移输入，不再作为运行时检索数据源。

## 1. 组成

- `models.py`：定义 `MemoryEntry`、`Scope`、`Kind`、`Status`、`SourceType` 和运行上下文。
- `store.py`：负责 SQLite schema、连接生命周期和事务。
- `service.py`：负责写入、检索、版本更新、状态转换和迁移导入。
- `injector.py`：负责确定性排序、数量/Token 预算和 Prompt 上下文格式化。
- `legacy.py`：扫描旧记忆文件并将可安全导入的记录转换为 SQLite 记录。
- `__init__.py`：对运行时提供 `create_memory_service` 等公共 API；保留的兼容名称只委托到新服务。

业务代码应通过一个显式创建的 `MemoryService` 访问记忆。服务需要明确的数据库路径；运行时组合根负责创建并共享同一个实例。

本轮已将 Agent Loop、Main、Headless、CLI 和 CyberneticOrchestrator 切换到上述入口；旧
Pipeline/Reranker/Vector/Curator/Timeline 文件目前仅保留在工作区，尚未删除。它们已不再是
运行时检索链路，但删除属于不可逆清理，需在确认兼容引用（尤其 `cybernetic_ablation.py` 的
控制器兼容入口）后执行。

## 2. SQLite 数据模型

schema 版本为 `1`，核心表为 `memory_entries`，包含：

`id`、`scope`、`kind`、`key`、`content`、`status`、`project_key`、`branch_name`、`source_type`、`source_session_id`、`source_turn_id`、`version`、`supersedes_id`、`content_hash`、`created_at`、`updated_at`、`expires_at`。

`metadata` 表保存 schema 版本和迁移 marker。数据库写操作使用事务；每条连接在读写完成后都会关闭，避免 Windows 下数据库文件被占用。

## 3. Scope、Status 和 Source

Scope 有三种：

- `global`：跨项目可见。
- `project`：仅当前项目可见，需要稳定的项目 key。
- `branch`：仅当前项目的当前 Git 分支可见，需要项目 key 和分支名。

Status 是生命周期状态：

- `pending`：候选记录，不参与检索或 Prompt 注入。
- `active`：可检索、可注入的记录。
- `archived`：暂时停用，可通过 restore 恢复。
- `superseded`：被新版本替代。
- `rejected`：被人工拒绝，不能检索。

Source 记录来源：`explicit_user` 表示用户明确写入，`verified_task` 表示经过本轮验证后生成的候选，`migration` 表示从旧文件导入。

## 4. 写入与安全规则

用户明确写入可以直接成为 `active`。模型或反思产生的内容必须先调用 `propose` 进入 `pending`，经过人工 `approve` 后才可成为 `active`；没有工具验证证据的反思不得绕过这个状态。

所有写入路径都会检查疑似凭据、令牌、密码和类似敏感信息。迁移同样执行检查，敏感内容不会进入 active，也不会被检索。迁移按来源使用原子事务：实际导入失败时不写 marker，下一次运行仍可重试；重复记录通过稳定 hash 去重。

## 5. 确定性检索与单次注入

检索只读取当前上下文可见、状态为 `active` 且未过期的记录。排序使用匹配分数、scope 优先级、更新时间和 ID 作为稳定次序，不依赖向量数据库、LLM reranker 或真实 Provider。

Prompt 注入由新 `MemoryInjector` 完成。它按本轮任务生成一次 bounded context，并受最大记录数和 Token 预算限制。记忆块是 advisory context，不能覆盖系统指令、权限规则或工具安全策略。Runtime 每个 turn 只应调用这个新 injector 一次。

## 6. CLI 生命周期命令

```text
/memory status
/memory list
/memory pending
/memory approve <id>
/memory reject <id>
/memory update <id> <new-content>
/memory archive <id>
/memory restore <id>
/memory delete <id> --confirm
```

单独输入 `/memory` 等价于 `/memory status`。`delete` 是不可逆的 purge 操作，必须带显式 `--confirm`（或等价确认词）；没有确认时服务会拒绝操作。

## 7. 验收命令

L0 契约测试：

```powershell
python -B -m pytest -q --tb=short -p no:cacheprovider tests/contracts
```

新记忆核心测试：

```powershell
python -B -m pytest -q --tb=short -p no:cacheprovider tests/memory
```

L1 和 L2 仍按 `tests/contracts/README.md` 中的确定性命令执行。测试使用临时目录和脚本化适配器，不调用真实模型，也不应把真实记忆内容、凭据或令牌写入文档和测试夹具。
